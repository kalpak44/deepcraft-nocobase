# deepcraft-nocobase

Deploys nginx onto `nocobase-lxc`, a container in a Proxmox homelab. The container
itself is provisioned and hardened by
[`homelab-infra`](https://github.com/kalpak44/homelab-infra) — this repo only
deploys onto it.

## What's here

```
ansible/                        playbook + nginx role (serves port 80)
.github/workflows/deploy.yml    deploys on push to main
```

## Access

| From | URL |
|---|---|
| Internet | <https://deepcraft-nocobase.pavel-usanli.online> |
| Home LAN | <http://192.168.1.5/> |
| SSH | `ssh -p 22022 root@192.168.1.5` (key only, no password) |

The public URL goes through a Cloudflare tunnel, so **no port is open on the
router**. Cloudflare handles HTTPS at its edge and the container only ever serves
plain HTTP on port 80.

## Deploying

Push to `main` touching `ansible/**`, or run the **Deploy** workflow manually from
the Actions tab.

The container isn't reachable from the internet, so the runner joins the Cloudflare
Zero Trust network first, then connects over SSH:

```
GitHub runner → WARP → Cloudflare → tunnel → 192.168.1.5:22022
```

To run it yourself from the home network:

```bash
cd ansible
export NOCOBASE_HOST=192.168.1.5 NOCOBASE_SSH_PORT=22022 NOCOBASE_SSH_USER=root
ansible-playbook playbook.yml --private-key /path/to/id_ed25519
```

The key is generated by Terraform in `homelab-infra`; get it with
`just output proxmox nocobase-lxc ssh_private_key`.

## Pointing your own domain at it

Your domain can stay with your current DNS provider — you only need to add one
record. Apex domains aren't supported, so use a subdomain.

**You add**, on your DNS provider:

| Type | Name | Value |
|---|---|---|
| CNAME | `app` | `deepcraft-nocobase.pavel-usanli.online` |

**We add**, on our side: `app.yourdomain.com` as a Cloudflare custom hostname, plus
a tunnel route for it.

Cloudflare then issues and renews an HTTPS certificate for **your** hostname
automatically, and `https://app.yourdomain.com` serves this site.

> Not yet enabled. It needs the `SSL and Certificates` permission added to the
> Cloudflare API token in `homelab-infra` before the custom hostname can be
> created.

## Repository secrets

| Name | What it's for |
|---|---|
| `NOCOBASE_HOST`, `NOCOBASE_SSH_PORT`, `NOCOBASE_SSH_USER` | where to connect |
| `NOCOBASE_SSH_PRIVATE_KEY` | deploy key |
| `CF_TEAM_NAME`, `CF_WARP_CLIENT_ID`, `CF_WARP_CLIENT_SECRET` | joins the runner to the network |
| `POSTGRES_HOST`, `POSTGRES_PORT` | `192.168.1.4`, `5432` |
| `REDIS_HOST`, `REDIS_PORT` | `192.168.1.6`, `6379` |

Postgres and Redis are host and port only — credentials live in the homelab's
Vault. Both are reachable **from the container**, not from CI.
